## Project Overview

This project provides a serverless file upload solution that allows web page forms to upload files directly to AWS S3 using pre-signed URLs generated by an AWS Lambda function. The architecture bypasses traditional web servers, enabling scalable file uploads from static websites.

## Architecture

The system has three components that work together:

1. **Frontend (src/frontend/)**: HTML form with jQuery-based JavaScript that intercepts form submissions
2. **Lambda Function (src/lambda/)**: Node.js 12.x function that generates pre-signed S3 upload URLs
3. **AWS Infrastructure**: S3 bucket, API Gateway, and IAM configuration

### Request Flow

1. User selects file in HTML form (upload.html)
2. JavaScript (upload.js) intercepts form submission
3. JavaScript calls Lambda function via API Gateway with filename and content type
4. Lambda generates pre-signed S3 URL with randomized filename prefix (6 random chars + separator + original filename)
5. JavaScript receives URL and uploads file directly to S3 via PUT request
6. Progress bar updates during upload

## Key Files

- **src/lambda/index.js**: Lambda handler that generates pre-signed URLs using AWS SDK. Reads configuration from environment variables (ACCESSKEYID, SECRETACCESSKEY, REGION, UPLOADBUCKET, UPLOADFOLDER, FILENAMESEP)
- **src/frontend/upload.js**: jQuery-based upload orchestration with progress tracking. Requires AWS API Gateway URL to be configured on line 15 (getUploadURLURL variable)
- **src/frontend/upload.html**: Simple file upload form
- **src/frontend/upload.css**: Basic styling for form and progress bar

## Configuration Requirements

### Lambda Environment Variables
The Lambda function requires these environment variables:
- `ACCESSKEYID`: IAM user access key with S3 PutObject permissions
- `SECRETACCESSKEY`: IAM user secret key
- `REGION`: AWS region where S3 bucket exists (e.g., "us-west-2")
- `UPLOADBUCKET`: S3 bucket name
- `UPLOADFOLDER`: Path prefix for uploads (must end with "/")
- `FILENAMESEP`: Separator between random prefix and filename (e.g., "----")

### Frontend Configuration
- API Gateway endpoint URL must be set in upload.js:15 as the value of `getUploadURLURL`

## Deployment Notes

- Lambda function must be deployed to AWS with proper IAM execution role
- API Gateway must have CORS enabled for browser-based access
- S3 bucket requires CORS configuration to allow PUT requests from browser origins
- IAM user credentials (used by Lambda) need GetObject and PutObject permissions for the target S3 bucket
- No build process required - files are deployed as-is

## Testing

To test the Lambda function directly in AWS Console:
- Use the "apigateway-aws-proxy" event template
- Replace the body with: `"fileName": "testFileName", "contentType": "text/html"`
- Successful response includes `uploadURL` (pre-signed S3 URL) and `filename` (randomized name)

To test end-to-end:
- Open upload.html in a browser
- Select a file and click Upload
- Check S3 bucket for file in configured UPLOADFOLDER path

## Important Implementation Details

- Filename collision prevention: Lambda prepends 6 random characters from AWS request ID to all uploaded filenames
- Default content type: "application/octet-stream" used if contentType not provided
- Progress tracking: XMLHttpRequest upload progress events drive the progress bar
- CORS headers: Lambda response includes "Access-Control-Allow-Origin: *" for browser compatibility
- Synchronous upload URL fetch: JavaScript uses `async: false` in the API Gateway call to ensure URL is available before upload starts
